## 已完成阶段 6：受控重复实验与可读报告

目标是形成一条有限的工作流：

```text
显式实验计划 → 全部场景预检查 → 有预算的串行求解
→ 每次结果独立复核 → 同口径分组与描述统计 → JSON + Markdown 报告
```

沿用现有 Python 服务、Pydantic 和本地文件，无需先引入调度框架或数据库。
这是让现有情景分析可用于决策讨论的一步，也为后续自然语言层提供明确的工具输出。

### 具体交付

1. **显式实验计划。** 记录基准、完整的变体 `ScenarioSpec`、backend 选择要求、
   重复次数、最大调用次数、每次时限及预算。先评估所有场景，遇到不兼容要求
   在启动前返回原因；不自行改写场景或生成无限参数组合。
2. **有界串行执行。** 复用 `solve_selected()`；为每次调用分配唯一 run ID，保存
   计划快照、选择记录和实际状态。约束拒绝、启动失败、无候选超时、含候选超时、
   验证失败和成功分别记录；批次的失败处理策略必须明确，禁止隐式重试或切换模型。
   批次记录保留已完成的运行，不覆盖历史产物。
3. **描述统计。** 明确展示计划数、实际调用数和复核通过的候选数，以及各状态的
   数量。仅对同一场景、同模型和相同搜索条件下的有效候选汇总目标值等指标的
   最小值、中位数、最大值及样本数；场景间展示观测差异。输入或模型签名不同
   必须分组或拒绝合并，不把失败、无解或不可比结果填成零。
4. **确定性的可读报告。** 从经过验证的结构化数据生成 JSON 和 Markdown，包含
   场景变化、模型口径、结果分布、未完成/失败记录、舍入与随机波动限制，并引用
   run ID 和证据路径。先用模板渲染，所有结论能回到输入或验证结果，不依赖 LLM。

重复运行的编号只是实验索引，不能伪装成 solver seed。少量连续运行也不能默认
视为相互独立的统计样本。首版只报告描述统计，不声称显著性、因果效应或最优性；
不把不同 backend 的原始目标值放在同一张优劣排行榜中。
